# 会话失效后的登录跳转

2026-10-17：浏览器业务请求返回 HTTP 401 时，统一用完整页面导航替换当前页面，进入 `/login?reason=session_expired`。登录页显示“会话已超时或已失效，请重新登录”，不挂载聊天运行时，也不请求对话历史，避免 401 循环。403 权限拒绝和普通网络错误保持原有语义。

`(workspace)` 路由组承载对话、操作、审批与会话页面，URL 不变。登录页和构建静态资源仅开放匿名 GET/HEAD，网关仍清理外部转发身份头，业务页面/API 的认证和授权不变。登录按钮继续通过 OAuth2 Proxy → Keycloak，返回地址固定为 `/`，不采纳外部传入的返回地址。

客户端对并发 401 只发起一次跳转；保留当前对话的本地标识与服务器历史，不自动重发中断的 POST 请求。已打开的旧页面需要刷新一次以加载新版代码。

验证：

- `npm run test:session`：6 项通过，覆盖并发 401、工作区离开状态、403、流式请求透传、网络异常及登录页避免循环。需要 Node.js 22.18+；与部署镜像和 CI 的 Node 22 一致。
- Docker 构建中的 TypeScript 检查、Next.js 生产构建均通过；Nginx 配置校验通过并已重载。
- 匿名协议检查确认超时页 200、CSS/JS 类型正确、业务 API 401、登录入口 POST 403、认证返回目标固定。
- 内置浏览器中短暂使本地 admin 测试令牌失效，点击已有对话触发真实 401，自动进入超时登录页；随后原样恢复测试前策略。点击重新登录后返回同一对话，已保存的历史完整恢复。没有更改用户权限或保存的业务记录。

这些客户端用例已接入 Web CI、本地 `scripts/verify.sh web` 以及镜像构建；匿名入口检查加入 `scripts/verify-gateway.py`。本次未运行该脚本中的全套用户策略变更及重放验收，只运行了上面的独立协议检查。
