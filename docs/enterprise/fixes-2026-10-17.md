## Repairs recorded then

### I02: Entity and field binding

The then-existing `business_facts.py` normalized successful tool results into entity, alias, field, value, currency, and evidence pointer. Explicit quantities/amounts/states were checked only after resolving their entity. Ambiguous multi-object references, conflicting facts, missing/wrong currency failed. Totals could not borrow unit prices; business state could not borrow source state. Capability checks no longer disabled all object-ID checks.

Three counterexamples—wrong currency, swapped customer counts, swapped order amount/state—became regressions alongside valid controls. Added unit-price/total confusion, omitted entity attribution, conflicting evidence, and missing currency. Independent hand-written inputs/boolean expectations did not reuse production gold helpers. E2 checked all matched calls instead of only the last value set.

Policy was `business-facts-v2`. `NO_PROTECTED_CLAIMS` meant no recognized protected assertion, not complete factual support. The parser had limited grammar and did not cover all pronouns, cross-sentence references, arbitrary tables, tax, conversions, or fields. Conservative ambiguity could falsely refuse. Runtime/scorer shared parsing; independent regressions were not a universal independent semantic judge. These limitations motivated the later closed evidence plan.

### Cancellation and latency

Cancellation no longer saved unverified model messages; previous committed history remained. Injected partial-text cancellation proved no SSE/history publication. Added `operion.run.first_verified_text_ms`, distinct from first SSE event and browser paint.

### I16: Database lifecycle

Offline removed inherited test DSN. `test_postgres.py` created owned `postgres:16` containers with random password/loopback port/name/labels and no business volumes, issuing an in-process capability only after readiness. Direct DSN-only destructive tests failed before connecting. Cleanup verified ownership before removal; CI used the same runner.

Unavailable Docker failed rather than using an existing database. `finally` cleaned normal failures; OS kill/daemon failure could leave containers. Inspect only `operion.test-owner` resources rather than bulk-deleting others.

## I15: Implemented minimal case runner

```bash
scripts/verify.sh offline
scripts/verify.sh postgres
scripts/verify.sh case
scripts/verify.sh case fact-binding --layer domain
scripts/verify.sh case wrong-answer --layer agent
scripts/verify.sh case mcp --layer mcp

```

[evaluations/developer/cases.json](../../evaluations/developer/cases.json) then defined nine case/layer combinations: legal read, scope denial, source failure, wrong answer, cancellation, fact binding, real MCP, database protection. Scripted `FunctionModel` exercised local API/SSE; MCP spawned real initialize/tools-list/tools-call with denied/illegal inputs. No live/browser layer; unsupported selections errored rather than skipping silently.

Each `reports/developer/<run-id>/` included:

- `manifest.json`: commit, tracked-diff hash, source/test/fixture/case hashes, locks, Python, model/data mode, status.
- Per-combination JSON/log: count/failure/error/skip, expected/actual assertion differences, business expectations, rerun.
- Escaped `index.html` and `junit.xml` for local/CI review.

Atomic incremental manifest updates retained RUNNING/partial logs. Timeout/no result was BLOCKED; skip SKIP; only every mandatory combination PASS returned 0. CI uploaded evidence. Forced failure/mandatory skip/empty selection self-tests could not succeed. Public fixtures only; no private ERP/credentials/real-model content.

This was minimal I15, not unified tool payload/protocol/request/span/model replay, complete timelines, semantic diff, or browser traces.
